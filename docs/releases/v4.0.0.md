# nixpkger 4.0.0

This release rewrites nixpkger's Python internals, adds packages from
soltros_nixpkgs, and supports configurations whose modules live outside the
usual `/etc/nixos` layout.

## Packages from soltros_nixpkgs

Install repository packages with the `soltros.` prefix:

```sh
nixpkger search soltros.
nixpkger install soltros.termsmith soltros.waterfox
nixpkger update --source soltros
```

The integration saves the repository revision and content hash in your package
module. Later rebuilds reuse that revision until you update it. No manual
overlay or flake input is required. Categories support the same commands.

## Flakes and module discovery

```sh
nixpkger --flake ~/my-nixos#desktop install soltros.termsmith
nixpkger --flake ~/my-nixos#desktop \
  --apps-file hosts/desktop/modules/apps.nix list
```

- `--flake` accepts a local directory or `flake.nix`, plus an optional host.
- nixpkger searches the selected directory recursively for `apps.nix`.
- `--config-dir` chooses a separate search directory.
- `--apps-file` selects a specific module, including one outside that directory.
- Multiple matches require an explicit choice.
- `--module-file` selects the module used for category imports and channel rebuilds.
- `--impure` replaces the separate impure script workflow.

The selected package file must already be imported by the target configuration.
Discovery does not evaluate the host's module graph or add imports automatically.

## Fixes and internal changes

- Four copies of the main program now use one Python core.
- Package edits match complete attributes and preserve comments and unrelated lists.
- Unsupported Nix expressions produce an error instead of being rewritten.
- Modules are syntax-checked before writes and backed up before replacement.
- File writes are atomic. Failed writes or rebuilds restore the previous files.
- Restore copies snapshots instead of consuming them, and backs up the file being replaced.
- Backup names are unique, including when created in quick succession.
- Unchanged package lists skip writes and rebuilds.
- Category names are validated, and missing categories are not created during removal.
- Missing arguments and failed commands return errors consistently.
- Search and garbage collection no longer depend on an `apps.nix` file.
- Mutating commands use a configuration-directory lock.
- Failed flake updates restore the previous lock file.
- The installer has been replaced and no longer installs packages into a Nix profile.
- `nixpkger --version` reports the installed version.

## Upgrade from v3

Requires Python 3.9 or newer and the NixOS command-line tools. There are no
third-party Python dependencies.

Extract a release source archive and run `sh install.sh` inside it. The program
installs under `~/.local/share/nixpkger`, with its launcher in `~/.local/bin`.
Replace old `~/scripts/nixpkger` aliases or PATH entries. Existing Nix modules
can stay where they are; use the file options for custom layouts.

Use `--flake` and `--impure` instead of swapping `main.py`. The old variant
filenames remain available as compatibility entry points in the source tree.

Category removal is now noninteractive. System updates no longer run the old
`nix-env -u` profile update. Soltros package pins are updated separately with
`update --source soltros`.

## Validation and limits

The release was checked with the Python regression suite, real Nix syntax and
binding evaluation tests, an installer smoke test, and live repository search
and Termsmith derivation evaluation. No live NixOS activation was tested.

Automatic package editing supports plain attribute lists. Complex expressions
still require manual editing. Restoring files after a failed rebuild does not
undo a partially completed system activation. Snapshots cover the selected
package module, not the whole system. New modules in Git-backed flakes must
be tracked before Nix can use them.

The attached source archives contain the application, documentation, and tests.
`SHA256SUMS` contains their checksums.
